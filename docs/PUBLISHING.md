# Публикация в App Store (и Google Play)

Сборка идёт в облаке через **EAS** (сервис от создателей Expo), поэтому Mac не нужен. Путь такой: сборка → TestFlight (тестирование на своём iPhone и у друзей) → отправка на проверку в App Store.

Перед публикацией приложение должно работать с настоящими TMDB и Supabase (см. [SETUP.md](SETUP.md)).

---

## 1. Что нужно заранее

| Что | Где | Цена |
|---|---|---|
| Apple Developer Program | [developer.apple.com/programs](https://developer.apple.com/programs/) | $99 в год |
| Аккаунт Expo | [expo.dev/signup](https://expo.dev/signup) | бесплатно (на бесплатном тарифе ограниченное число облачных сборок в месяц) |
| Политика конфиденциальности по публичной ссылке | шаблон: [legal/privacy-policy.md](legal/privacy-policy.md) | бесплатно |
| Почта поддержки | любая ваша почта | — |

Регистрация в Apple Developer Program занимает от нескольких часов до пары дней. Проверьте заранее, доступны ли регистрация и оплата в вашей стране.

**Где разместить политику конфиденциальности:** заполните шаблон и опубликуйте его как страницу в Notion, Telegraph (telegra.ph), Google Docs («Опубликовать в интернете») или GitHub Pages. Нужна просто открытая ссылка.

## 2. Подготовить проект

### 2.1. Уникальный идентификатор приложения

В `app.json` добавьте свой Bundle ID (латиница, обычно перевёрнутый домен или имя):

```json
"ios": {
  "bundleIdentifier": "com.vashe_imya.copione",
  "supportsTablet": false,
  ...
},
"android": {
  "package": "com.vashe_imya.copione",
  ...
}
```

Тут же можно поменять название (`"name"`), иконку (`assets/images/icon.png`, 1024×1024) и версию (`"version"`).

### 2.2. Ссылки в `.env`

```
EXPO_PUBLIC_PRIVACY_URL=https://...ваша политика...
EXPO_PUBLIC_SUPPORT_EMAIL=you@example.com
```

Они появятся в **Настройки → О приложении**.

### 2.3. Подключить EAS

```bash
npm install -g eas-cli
eas login
eas init
```

`eas init` создаст проект на expo.dev и допишет его id в `app.json`.

### 2.4. Переменные окружения для облачной сборки

⚠️ Файл `.env` **не попадает** в облачную сборку (он в `.gitignore`, и это правильно). Значения нужно завести в EAS:

**Вариант 1 (проще):** на [expo.dev](https://expo.dev) откройте проект → **Environment variables** → добавьте `EXPO_PUBLIC_TMDB_KEY`, `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY`, `EXPO_PUBLIC_PRIVACY_URL`, `EXPO_PUBLIC_SUPPORT_EMAIL` для окружения **production** (видимость можно оставить *Plain text*: эти значения всё равно попадают в приложение).

**Вариант 2 (из терминала):**

```bash
eas env:create --environment production --name EXPO_PUBLIC_TMDB_KEY --value "..." --visibility plaintext
# повторить для остальных переменных
```

## 3. Сборка и TestFlight

```bash
eas build --platform ios --profile production
```

EAS попросит войти в аккаунт Apple Developer и сам создаст сертификаты и профили (соглашайтесь на предложения по умолчанию). Сборка в облаке занимает 10–30 минут.

Затем отправьте сборку в App Store Connect:

```bash
eas submit --platform ios --latest
```

Через 10–30 минут обработки сборка появится в [App Store Connect](https://appstoreconnect.apple.com) → ваше приложение → **TestFlight**:

1. Добавьте себя во **внутренние тестировщики** (Internal Testing, до 100 человек из вашей команды, без проверки Apple).
2. Установите приложение **TestFlight** на iPhone и примите приглашение.
3. Для друзей подойдёт **External Testing**: по ссылке, после короткой бета-проверки Apple.

## 4. Страница в App Store

В App Store Connect → **App Store** заполните:

- **Название и подзаголовок**, например «Copione — кино и музыка».
- **Описание и ключевые слова**: кинодневник, рецензии, сериалы, альбомы, оценки, Letterboxd…
- **Скриншоты** для самого большого iPhone (6.9″, 1320 × 2868). Удобно снять их в симуляторе или на телефоне через TestFlight.
- **Категория**: Развлечения (Entertainment), дополнительная — Музыка.
- **Privacy Policy URL** и **Support URL**.
- **Возрастной рейтинг**: в анкете честно отметьте, что в приложении есть пользовательский контент.
- **App Privacy (конфиденциальность)**: приложение собирает
  - *Contact Info → Email Address*: для функциональности, связано с пользователем;
  - *User Content → Other User Content* (рецензии, комментарии): функциональность, связано;
  - *Identifiers → User ID*: функциональность, связано;
  - **Tracking: No** (рекламы и трекинга нет).
- **App Review Information**: обязательно дайте **тестовый аккаунт** (почта и пароль), иначе проверяющий не сможет войти. Заранее создайте его в приложении и подпишите на пару людей, чтобы лента не была пустой.

Затем выберите сборку и нажмите **Add for Review**. Проверка обычно занимает 1–3 дня.

### Что Apple проверяет и что уже сделано в коде

| Требование Apple | Где в приложении |
|---|---|
| Удаление аккаунта внутри приложения (5.1.1(v)) | Настройки → Удалить аккаунт |
| Пользовательский контент (1.2): правила, жалобы, блокировка | Правила при регистрации; «Пожаловаться» и «Заблокировать» в профилях и рецензиях |
| Реакция на жалобы в течение 24 часов | **Ваша задача**: таблица `reports` в Supabase (см. SETUP.md, п. 4.5) |
| Политика конфиденциальности | Ссылка в настройках (`EXPO_PUBLIC_PRIVACY_URL`) и в App Store Connect |
| Без лишних разрешений | Микрофон и фоновое аудио отключены в `app.json` |
| Шифрование (export compliance) | `ITSAppUsesNonExemptEncryption: false` уже стоит, вопрос не возникнет |
| Sign in with Apple | Не требуется: вход только по почте, без Google/Facebook |

Если Apple отклонит заявку, в Resolution Center будет причина. Обычно хватает поправить описание или тестовый аккаунт и ответить в том же окне.

## 5. Обновления

Новая версия выпускается так же: поменяйте `"version"` в `app.json`, затем `eas build` → `eas submit` → в App Store Connect создайте новую версию и отправьте на проверку. Номер сборки увеличивается автоматически.

*По желанию:* мелкие исправления можно выкатывать без проверки Apple через OTA-обновления (`npx expo install expo-updates`, `eas update:configure`, затем `eas update`).

## 6. Android (Google Play)

Код тот же, отдельно ничего писать не нужно.

1. Зарегистрируйтесь в [Google Play Console](https://play.google.com/console) (разовый платёж $25).
2. Соберите:
   ```bash
   eas build --platform android --profile production
   ```
   Получится файл `.aab`.
3. Создайте приложение в Play Console и **первый раз загрузите `.aab` вручную** (дальше можно через `eas submit --platform android`).
4. Заполните анкеты: Data safety (по аналогии с App Privacy выше), возрастной рейтинг, политика конфиденциальности, целевая аудитория.
5. Для новых личных аккаунтов Google требует сначала провести **закрытое тестирование** (на момент написания: не меньше 12 тестировщиков в течение 14 дней), и только потом пускает в открытый доступ.

## 7. Если планируете зарабатывать

- **TMDB**: бесплатный ключ только для некоммерческого использования. Для рекламы или подписки нужна коммерческая лицензия, пишите в TMDB.
- **Apple iTunes Search API**: бесплатный, но данные должны вести к Apple Music (кнопка «Слушать в Apple Music» уже есть).
- **Supabase**: бесплатный тариф щедрый, но бесплатный проект засыпает после недели без активности. Для живого продукта нужен Pro ($25/мес).
- Встроенные покупки (подписка Pro) в iOS обязаны идти через In-App Purchase Apple.
